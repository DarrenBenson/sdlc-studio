The known-issues page, `docs/known-issues.md`, is cut for v6.5.0 with
`known_issues.py write --release 6.5.0`. It states the v6.5 bar, fewer than 50 open bugs at the
tag and none at Medium or above, keeps the v6.0 bar below it as history, and lists every open
finding by id with its count; the same command fills the 6.5.0 notes' disclosure line with that
count. `tools/known_issues.py` records the v6.5 bar, so a 6.5 cut states it while a cut for 6.0
to 6.4 still states v6.0's. The page's ship-open sentence names only the severities its table
holds, so a page whose table holds no Medium no longer says Medium findings ship open. The
evidence page, `docs/evidence.md`, is regenerated with `sprint_report.py evidence` through
RPT0045, run twenty-six's report. `tools/tests/test_lean_release_disclosure_v65.py` judges the
release, the v6.5.0 tag once it exists, else the commit that last wrote the page (the working
tree while a freshly written page is uncommitted): there
`known_issues.py check` exits 0, the page's v6.5 section leads with that bar, the notes' line
equals the page's count, and fewer than 50 findings are open with none at Medium, High or
Critical. It runs `known_issues.py bar` at the tag, or on the working tree before the tag exists.
