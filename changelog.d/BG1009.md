`verify_ac revert-check` now judges only what it measured. A verifier that times out, cannot
start, or exits clean without passing (a pytest run that skipped part of its selection) is
reported as `unmeasured`, never as the red that passes a unit. A revert that would change no
byte, because the base holds the production files as they stand, reports the unit as not judged
(exit 3) before any verifier runs, instead of refusing it for a change it never removed.
`help/verify.md` states the four verdicts and their exit codes, with an example of each.
