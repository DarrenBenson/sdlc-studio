- **`artifact.py new` accepted a `Verify:` selector that `file_finding` refused.** US0667's
  criterion says BOTH writers refuse a selector naming a test that does not exist, it was stamped
  `Verified: yes`, and only one of them did - because its test drove only the filer. The cause was
  a reader that saw one writer's shape: the finding filer carries criteria as prose with an inline
  `**Verify:**` marker, while `artifact.py new` carries `--verify` as a list of BARE selectors and
  renders the marker later, so the guard's selector extraction found nothing to check on that
  path. A story minted through `new` could therefore carry a verifier pointing at nothing while
  the identical bug filed through the other door was refused. Both paths now route through the one
  seam, and the test drives both writers rather than asserting half its own criterion.
- **A refused selector now names the near miss.** A refusal saying only "this does not resolve"
  sends the author back to grep, which is the step they skipped to get there. The overwhelmingly
  common cause is a real test named slightly wrong - this repository's scar is a class name typed
  as it ought to have been rather than read off the file, twice in one session - so
  `verify_ac.selector_near_miss` answers the right-file, right-method, wrong-class case exactly,
  and falls back to the closest collected name. It reuses `_build_command` and the collection
  cache rather than parsing selectors a second time, and returns None whenever it has nothing
  confident to say.
