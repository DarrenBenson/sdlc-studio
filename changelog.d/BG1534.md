`verify_ac.py ts-check` now resolves the pytest node ids a test spec's AC Coverage Matrix names.
A passing row whose Test Cases cell names a test file and test that nothing in the tree defines
is a finding naming the row, where before any filled cell over a pass word read as clean. A
cell naming no test file, a manual check, is not resolved. pytest's doctest form,
`file.py::module.name`, resolves only when the file holds that doctest: the module, named by
its directory for a package's `__init__.py`, or what a class, function or method it defines
still binds once it has run, never one inside a function. Of several definitions of one name
the last is bound, save that a property's `.setter` or `.deleter` keeps the property and its
docstring. An import or `del` after a definition leaves none, a definition under an `if`,
`try`, loop or `with` counts, a `finally` block always runs, and where which one is bound
depends on the branch taken, any that may be counts. What an assignment, or another
property's `.setter` or `.deleter`, binds to a name is not read, so it is not reported. The
docstring must hold an example the standard library's doctest parser finds, so a prompt
holding only a comment or nothing is none. The TS0002 mutation-check gate spec is
corrected to match: its US0052 AC4 row names the tests that story's Verify line runs, and its
US0054 AC1, AC2 and AC4 rows record the manual Verify lines left when the gate's mutation lane
was retired.
