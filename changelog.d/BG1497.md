`reference-config.md` documents every configuration key the scripts read: `sprint.fresh_session`
with its three modes and its default, `warn`, and keys it left out, among them
`complexity.cognitive_high`, `version_check.*`, `lessons.carried_max`, `triage.enabled`,
`test_execution.*` and `review.blocking_priority`, the keys read from a project's own file
alone in a new Other Settings section, and `report.enabled` in a Sprint Report section of its
own. `config-defaults.yaml` declares each with the value its script uses when it is unset, the
`pricing` keys among them, so an unconfigured project behaves and is priced as before. A test
now fails on any key either file lacks, naming the key and the file: one passed to
`config.get`, `config.feature_enabled`, `config.load_config` or `project_override`, as a string,
a constant, a loop value or a helper's parameter, or read from a block a reader or a helper
returns; it also fails on a read whose key it cannot resolve.
