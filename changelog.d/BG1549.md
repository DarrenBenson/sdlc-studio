<!-- section: Fixed -->

`docs/why-sdlc-studio.md` no longer says a bug reaches Fixed only when its criteria pass. It now
says what the gate in `transition.py` enforces: a story reaches Done only when its executable
criteria have passed, and a bug is refused Fixed when nothing speaks for the fix (no criterion
ticked and none carrying a `Verify:` line) or when a recorded run of its criteria is red. A
`Verify:` line that was never run does not refuse Fixed. `docs/whitepaper.md` said `sprint sign`
moves a bug to Fixed only if its criteria and recorded verification run speak for it; it now says
the sign moves the bug through the gate `transition.py` enforces, which refuses it on the same two
grounds. A test in `tools/tests/test_doc_claims.py` reads each sentence and semicolon clause of
both pages and refuses two claims the gate does not enforce: that a bug's criteria must pass or
have run, whether a page says Fixed comes only when, if, once or after its criteria, `Verify:`
lines or tests pass, are green or have run, or until or unless they do, or that they must, have to
or need to pass or run; and that a criterion never run refuses Fixed. BG1039, which stood at Fixed
on `Verify:` lines naming a test file that has never existed, now names the two one-list tests in
`tools/tests/test_prereq_list_is_ci_list.py` that pin its two criteria, carries a recorded green
run of both, and is held to that by a second test in `test_doc_claims.py`.
