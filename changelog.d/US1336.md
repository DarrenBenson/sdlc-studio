`routing.effort` now takes an entry per kind of unit, `docs`, `bug` and `code`, beside `builder`
and `reviewer`: each entry maps a role to an effort, and a role it leaves out takes the role
default. A unit is a bug by its id, else code when an Affects path ends in a code extension, else
docs, as `route.work_kind` classifies it. With any entry set, `sprint plan` stamps each unit's
own effort with its `kind`, and `sprint lane brief` names that effort and kind for the unit it
briefs. `sprint plan` exits 2 before it selects or writes anything on a key `routing.effort` does
not take, a role other than `builder` or `reviewer` in an entry, or an unknown effort, naming the
key and what it takes, and refuses a reviewer below its builder within a kind unless
`routing.effort.reviewer_below_builder` names a decision `decisions.md` records, printing that id
and the kind when it plans. The entries ship empty. What changes for an upgrader: a key
`routing.effort` does not know, misspelt or not (`reviwer: high`, say), now refuses the plan with
exit 2 and names the key, and `sprint lane brief` says the setting is not valid, where 6.4
planned and ignored the key. A `routing.effort` holding only the keys 6.4 documented, `builder`,
`reviewer` and `reviewer_below_builder`, plans and briefs as before.
