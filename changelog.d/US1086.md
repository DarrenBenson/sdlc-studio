- The TRD and the TSD describe the gate host a clone can configure. Both name `sdlc.gateHost`,
  `sdlc.gateSsh`, `sdlc.gateCloneId` and `SDLC_GATE_LOCAL`. The TSD's push stage says where the
  gate runs with a host configured (there, through `tools/remote-gate.sh`, the host's preflight in
  place of the local prerequisite check), with none (on this machine), and with
  `SDLC_GATE_LOCAL=1` (on this machine, for one push). A host that cannot be reached refuses the
  push rather than running the gate here. The TRD adds that `tools/run-suite.sh` runs on the same
  host, and that `remote-gate.sh doctor` and `enable-hooks.sh` report on it.
- `tools/tests/test_lean_gate_host_docs.py` reads the settings from the four scripts that choose
  or report where the gate runs: the pre-push hook, `remote-gate.sh`, `run-suite.sh` and
  `enable-hooks.sh`.
