`sprint.py close --dry-run` names each step on stderr as it starts (`close --dry-run: running
<step>`, the preflight as `prerequisites and gate`), so a slow preview can be told from a hung
one; before, nothing was printed until the verdict. The review-current check reads every
artefact's last commit time in one pass of the history (`git ls-tree` and one
`git log --name-only`), where it ran one `git log -1` per artefact, so the git processes it
starts no longer grow with the number of artefacts; an untracked artefact still reads its file
time, a merge whose artefact differs from each parent's, as a conflict's resolution leaves it,
still counts as its last change, and a project kept in a folder of its repository still reads
its commit times. On this repository's 4,231 artefacts that is 2 git processes and about 10
seconds on a loaded host, where one `git log -1` took about a third of a second each. The gate's
review-current lane reads the staleness once a run, where a stale review anchor made it read it
twice.
