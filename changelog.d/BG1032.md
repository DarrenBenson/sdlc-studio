- Further fixes to how a reviewer's verdict is recorded, after BG0950's second review:
  - **Code spans** are found as the review ledger finds them. A span opened by two backticks
    keeps a `;` inside it, as a one-backtick span does. A `;` followed by an origin tag inside
    a code span, such as a quoted prior finding, no longer starts a phantom finding.
  - **A stray closing bracket** with no opener, such as `a)` in a lettered list, no longer
    makes a later `;` inside brackets end the finding.
  - **The return contract** states that a `;` followed by an origin tag ends a finding even
    inside brackets, and that `\;` keeps it.
- **The history section of each review brief:**
  - It undoes the ledger's escapes inside code spans too, so rows written before spans were
    left alone show `test_config`, not `test\_config`.
  - It keeps a finding that merely quotes a pre-existing tag, judging each finding by its own
    origin tag.
