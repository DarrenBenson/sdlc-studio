- **The mutation ledger kept several live rows on one (unit, criterion, row) key, and the join
  took whichever was iterated last.** Re-registering a criterion after re-executing its mutant
  appended rather than replaced, and no command said so: measured on this repository's ledger,
  nineteen keys carried more than one live row, five of them naming different tests. `mutation.py
  audit` now names every such key with each row's verdict, test, target and hash, tags rows whose
  entry is stale, counts the keys whose rows name different tests or disagree on their verdict,
  exits 1 when any exist and is silent with exit 0 on a clean ledger. Correcting a row stays with
  `retract`, which costs a reason and leaves the correction on the record.
