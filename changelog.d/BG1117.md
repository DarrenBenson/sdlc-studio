- An author self-check record is bound to the unit's own change rather than to whole files
  (BG1117). `critic.py self-check record` keeps the commit the record was taken at, after the
  digest in the row's Digest cell (`<digest> at <commit>`), and `critic.py brief` admits a row
  whose digest matches the unit's Affects content as it stands, or as it would stand with other
  units' later commits set aside:
  - a commit since the record whose subject names a unit id, none of them this unit's, is
    another unit's and is set aside, so a later unit's commit to a shared file no longer stales
    an earlier unit's record;
  - the author's own further edit still stales it: an uncommitted edit, a commit whose subject
    names this unit, and a commit whose subject names no unit id are never set aside;
  - a record taken at a commit HEAD does not descend from, a row written before this change
    (it names no commit) and a project outside git are judged on the content as it stands, as
    before.
- The digest leaves out what the review tooling itself writes: the self-check log
  (`author-self-checks.md`), the verdict log (`critic-verdicts.md`) and the runtime notes under
  `sdlc-studio/.local`. A unit whose Affects declares one of them, or a directory holding one,
  is no longer staled by its own record, by another unit's verdict or by its own brief. Such a
  unit's digest moves once with this change, so its earlier record reads as stale.
