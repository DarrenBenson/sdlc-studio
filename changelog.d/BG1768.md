`mutation.py run --since REF` now judges a target whose uncommitted work is all staged, in a private copy of the index (`git checkout-index`) that is removed after the run, so a builder's diff-coverage pass over staged work runs instead of refusing. No mutant touches the working tree, and the index is never rewritten, even when a staged file's cached stat data is stale. The changed lines are the index's diff against `REF`, not against `HEAD`. The copy holds the staged content of every file, so an unstaged edit to a test or helper is not run, and a `--test` naming its tests by absolute path runs the working tree's tests, not the copy's. A red baseline on that route says the suite ran over the staged version of every file in the private copy, not over the working tree, and asks for the fix to be staged. A target with unstaged or untracked changes is still refused, and the refusal now names staging the work and re-running with `--since` beside `git worktree add` and commit or stash. The report marks the run isolated in a private copy of the index and names the repository's paths, never the copy's. (BG1768)
