`sprint plan` now names, per unit, the test modules outside its `Affects` that import or run a
`.py` file it declares, so a groomer sees the modules a change to that file can turn red before
the run starts. The list is advice beside the registry advice: it changes no exit code, batch or
grooming verdict under any `sprint.affects_check` mode, and `--format json` carries it as
`breakdown.test_advisories`, apart from `affects_advisories`. A test module is a `test_*.py` file
`git ls-files` lists under the project root, so an untracked module and the copies a worktree
under the project holds are never read. The human line names at most ten modules per script,
sorted, and ends `, +N more (--format json lists all)` when it leaves N out. On this repository
the scan reads 683 tracked test modules once per plan in under half a second.
