- **A lesson is a failure class that counts its repeats and reaches the work.** A committed
  store, `sdlc-studio/lessons.jsonl`, holds one row per failure class: `id` (the class code,
  `LC-001`), `class`, `rule`, `behaviour`, `inject` (plan, build, review), `hits`, `state`
  (active, graduated, retired) and `recorded_run`. A retro Try item names its class:
  `[LC-003] ...` adds a hit `{run, unit, source}` to that class instead of writing a new
  lesson, and `[new: <class name>] Rule. Behaviour.` records a new class (`| build, review`
  narrows where it is injected). A `new` tag naming a recorded class counts as a hit on it, and
  a re-run close counts a repeat once. An unknown code, an unknown phase or a new class with no
  behaviour sentence is refused by `retro.py validate` and `extract`, which writes nothing.
  Untagged Try items still go to the project lessons log, which is kept as history with the
  `lessons/LL*.md` files.
- **The plan output, every lane brief and the review brief carry the lessons injected at their
  phase**, as rule plus behaviour, at most five, most-repeated first, naming how many more are
  active. They replace the five curated `LESSONS-TOP.md` titles those briefs carried; an absent
  store is reported as none active and an unreadable one is named, never omitted.
