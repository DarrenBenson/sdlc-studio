<!-- section: Changed -->

- CI installs the suite's Python packages from `requirements-dev.txt`, the same file
  `tools/gate_prereqs.py` checks a clone against.
  - **What a test holds.** `tools/tests/test_prereq_list_is_ci_list.py` reads every `pip install`
    the ci job runs. Each must name that file as its only requirements file, or install only a
    named tool that is not a suite package.
  - **What it reads.** It reads the spellings its self-test lists: pip run several ways, with
    general options before `install`, and `-r` and `-c` separate, attached, clustered or long.
    It refuses a `PIP_REQUIREMENT` or `PIP_CONSTRAINT` variable and an install run from another
    directory. A pip config file or a wrapper script is not read.
  - **The file and corpus-verify.** The file includes no other. The scheduled corpus-verify job
    keeps its own shorter list, held to a subset of the file with no looser floor.
