The finding filer (`file_finding.py file`) and `artifact.py new` and `batch` now leave the shell
commands in a bug's Steps to Reproduce runnable. A line that is a command is written inside a
fenced block labelled `text`, with consecutive command lines sharing one block, and outside a
list its lines are kept byte for byte. A line is a command when it opens with one after an
optional `$` prompt, or when it carries a shell operator such as `&&` or `$(` outside a code
span, so a sentence holding one is fenced whole with its words as written. The prompt is
dropped, since a pasted prompt does not run and markdownlint refuses a block whose every
command shows one. A numbered or bulleted step whose body is a command keeps its marker, with an
empty HTML comment on the marker's line and the fence beneath it, so the criteria parser and
the fence labeller still pair the fence. A command on a step's continuation line is fenced at
that step's content column, so the list keeps its numbering. A fenced block the author wrote is
kept as written, and is closed if the author left it open, so it cannot swallow the next
section. A metadata declaration such as `**Waived:**` inside a command still has its bold
markers escaped, as in the prose, so no filed step declares a field the bug's head did not.
Before, the markdown-safety pass back-ticked identifiers such as `sdlc_md` inside the command,
which the shell then read as command substitution. The prose around a command is still safed,
and a steps value with no command in it is written as before.
