The finding filer (`file_finding.py file`) and `artifact.py new` and `batch` now leave the shell
commands in a bug's Steps to Reproduce runnable. A line that is a command is written inside a
fenced block labelled `text`, with consecutive command lines sharing one block, and outside a
list its lines are kept byte for byte. A command keeps in its block the lines the shell reads
as its own: the line after one ending on a backslash, unless that line is blank; every line up
to the one that closes a quote it left open; and a here-document's body up to the line that is
its delimiter, indentation aside. A quote no later line closes, or a delimiter no later line
is, takes no line with it, and a `'` between two letters or digits is read as an apostrophe, so a sentence
cannot take the prose after it. A line is a command when it opens with one after an optional
`$` prompt, or when it carries a shell operator such as `&&` or `$(` outside a code span, so a
sentence holding one is fenced whole with its words as written. The prompt opening a command is
dropped, since a pasted prompt does not run and markdownlint refuses a block whose every
command shows one. A numbered or bulleted step whose body is a command keeps its marker, with
an empty HTML comment on the marker's line and the fence beneath it, so the criteria parser and
the fence labeller still pair the fence. A command on a step's continuation line is fenced at
that step's content column, so the list keeps its numbering; inside a list, a command's lines
move to that column as a block, keeping their indentation relative to each other. A fenced
block the author wrote is kept as written but for one change, and is closed if the author left
it open, so it cannot swallow the next section. That one change applies inside an author's
block and a command's alike: a metadata declaration such as `**Waived:**` opening a line (after
an optional `>`) or following a ` · ` has its bold markers escaped, as in the prose, because
the bug's field reader takes such a declaration inside a fenced block for a field, and no filed
step may declare a field the bug's head did not. Before, the markdown-safety pass back-ticked
identifiers such as `sdlc_md` inside the command, which the shell then read as command
substitution. The prose around a command is still safed, and a steps value with no command in
it is written as before.
