<!-- section: Fixed -->

The finding filer (`file_finding.py file`) and `artifact.py new` now leave the shell commands in
a bug's Steps to Reproduce runnable. A line that opens with a command, after an optional `$`
prompt, is written byte for byte inside a fenced block, with consecutive command lines sharing
one block. The prompt is dropped, since a pasted prompt does not run and markdownlint refuses a
block whose every command shows one. A numbered or bulleted step whose body is a command keeps
its place with its body in a code span. A fenced block the author wrote is kept as written, and
is closed if the author left it open, so it cannot swallow the next section. Before, the
markdown-safety pass back-ticked identifiers such as `sdlc_md` inside the command, which the
shell then read as command substitution. The prose around a command is still safed, a steps
value with no command in it is written as before, and a command written mid-sentence is still
read as prose. `artifact.py batch` now labels the fences it writes, as `new` does.
