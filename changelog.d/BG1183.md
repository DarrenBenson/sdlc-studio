- A `migrate.py` dry run, and the test US0940 AC1 runs, take a fraction of the time they did
  (BG1183). They are criteria's verifiers, bound by `verify_ac run`'s default 120 s ceiling for
  US0926 AC1's dry run and the release gate's default 300 s for US0940 AC1.
  - migrate's conformance step collected each test file a stamped `pytest` selector on a Done
    story names, one `pytest --collect-only` after another: 266 files on this repository, and
    most of the run. The collections now run up to `min(cores, 8)` at a time, through the call
    the step makes, and the step runs beside them: for a file still being collected it waits,
    then reads the result from its cache. A dry run starts them before its first step.
    `--apply` starts them once its steps that write have run.
  - Each collection now writes bytecode under a private temporary directory that migrate removes
    afterwards (`PYTHONPYCACHEPREFIX`), so a module one collection compiled is read by the next.
    Before, bytecode writes were off. pytest's cache stays off, and the project's own files are
    left byte for byte as they were. The CLI turns SIGTERM into an exit, so a run that `timeout`
    stops still removes the directory, about 25 MB on this repository.
  - A dry run reads the artefact corpus through `sdlc_md.corpus_cache`, which took the sizing
    step from 21.7 s to 0.9 s (load 3 to 8). migrate makes its root absolute first, because the
    cache hands every caller the paths its first walk built, and a step that makes the root
    absolute itself cannot place relative ones. `--apply` reads the disk, as before.
  - Measured on this workspace (8 cores, 2026-11-03), the dry run printed the same report as
    before and took 151 s at load 5 to 12, against 415 s at load 2 to 7. That is still over the
    120 s ceiling at that load: both runs under `timeout 120`, started at load 4 and 5, ran into
    it, while two other agents' test suites shared the machine.
  - `tools/tests/test_lean_release_verify.py` no longer re-runs the five measured criteria whose
    Verify is a bare `pytest <node>`: US0021 AC1, US0042 AC2, US0047 AC1, US0284 AC4 and US0941
    AC5. Each names a test of this suite, which the push's full suite runs beside this one and
    the release lane's pytest batch answers in its own right. The test now checks that each
    still selects a test, the red no suite run reports. US0284 AC4 alone took 64 s (load 6 to
    11).
  - The other 14 it re-runs as the release lane runs the stories its batch leaves,
    `gate._verify_workers()` at a time, holding back to run alone after the pool any whose
    criteria name a `serial_only` test module. Each still fails the test when red. The module
    took 130 s and 133 s (load 4 to 14), against the 535 s BG1183 measured.
