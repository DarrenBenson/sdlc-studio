- The v6.2.0 release notes, `docs/release-notes-v6.2.0.md` (US1110). They open with what changed
  for a 6.1 user under four themes, each naming the units that delivered it, then list each change
  a 6.1 habit meets as a new refusal or a changed default beside what to do instead, and state
  that no 6.2 fragment is filed under Breaking or Removed. The upgrade path from 6.1 is reinstall,
  `migrate`, then `migrate --apply`, which for a 6.1 project restamps `sdlc-studio/.version` and
  changes nothing else. The open-defect count line carries the figures `known_issues.py` counts
  today, 174 (56 Medium, 118 Low), for the cut to refill.
- `tools/tests/test_lean_release_notes_v62.py` holds the notes to this:
  - each theme must name exactly its units, and a unit id anywhere else outside the known-issues
    and sources passages is refused, as is a figure whose sentence names no source;
  - each changed default or new refusal must sit in one bullet with its `Instead:` clause, and
    the no-Breaking statement must agree with the 6.2 entries;
  - the notes' own `migrate.py` steps are run, in their order, on a project v6.1.0's `init.py`
    made, and `critic.py brief` under `review.author_self_check` and
    `sprint.py goal-review record` with `rereview` are run too. Each runs against the v6.2.0
    tag's tree once the tag exists, and before then against this tree with its 6.1.0 version
    read as 6.2.0.
