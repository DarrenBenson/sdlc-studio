- **BG0527 - the one-run-slot gate stands down a step too early.** `run_state._is_spent` treats a recorded `sprint_goal_verdict` as proof a run is history, but the goal verdict is written *before* the close chain, not by it. So every run passes through a window in which its outcome still says `running`, its units are still at Review, and the guard protecting its close has already released the slot - long enough for the next `sprint plan --write` to open over it and strand the batch with no close, no cascade and no record that one was owed. Found while planning the next sprint by testing the premise "the previous run must close before the next can open" rather than assuming it; the premise is false today, on the live run whose own pre-flight reports twenty unmet prerequisites. The same predicate already excludes a failed close attempt for exactly this reason, on the stated ground that it is "the run most likely to be worked around" - the exclusion list simply stopped one item short.
