A run metered by two harnesses no longer adds a delegated total twice. `record_delegated_tokens`
takes a `harness`, stored on the record, and a record tagged to a harness whose reading already
holds its agents' spend (as the opencode reader's does) is left out of the run's total by
`_run_tokens_actual`, the retro's accuracy total and the report's Tokens figure. An untagged
record is added as before, so a Claude-only fan-out reads the same. Before, the all-or-nothing
`includes_subagents` flag added the whole delegated total beside an opencode session that had
already counted it.
The lane-run return (`sprint lane return`) now tags each delegated record it writes with the
harness of the lane run's reading, so the exclusion reaches a real record; a total a person
supplies with `--delegated-tokens` names no harness and stays untagged.
