### Fixed

- The release verify lane's red-criteria count now measures what it has always claimed to
  measure: acceptance criteria that fail on stories **already at Done**. It counted every story
  at any status. Across 670 stories that is 87 red in total and 20 on Done work; the other 67 sit
  on Ready, Superseded and Won't Implement stories - unbuilt or abandoned, never claimed
  finished - so a criterion failing there was never evidence of rot, while the lane's remedy text
  told readers to hunt them as renamed tests.

  It also explains why the corpus figure never held still. Its own baseline records the number
  moving 106, 53, 58, 50, 52, and a reading that could not be reproduced a day later against
  byte-identical stories because the denominator had changed. A population containing every
  un-started story moves whenever anybody grooms - and a `design` rung makes that structural
  rather than incidental, since its entire product is criteria that fail until the code exists.

  Excluded criteria are still executed and are now reported on their own line with each story's
  status, so the exclusion can be audited rather than taken on trust. An absent or unreadable
  status counts as a claim of completion: only an explicit non-completing status earns the
  exclusion, so it cannot be reached by deleting a line.

  The corpus baseline drops from 52 to 20 in the same commit, as the lane requires in both
  directions.

  Two defects found by a second review round, both in the first cut of this fix. A story
  status a project DECLARES in its own `.config.yaml` was recognised by the extended
  vocabulary and then found non-terminal by tables built from module constants, so it was
  silently exempted - a consuming project moving finished work to `Shipped` would have lost
  every regression on it, reported as "unbuilt or abandoned". Classification now asks the
  BASE vocabulary, so anything a project added fails closed like anything misspelt. And a
  pass reached through the exclusion ledger alone reported no scope, because that branch had
  never before been able to render one - restored, with the green denominator beside it.

  A third review round found the repair of the second had reintroduced the defect it names. The
  green figure restored to the exclusion-only PASS printed `executable` - everything that RAN,
  failures included - so a single line read `3/3 executable AC(s) green` beside `2 failing`. At
  the end state this change steers towards that is `1834/1906 green` with 67 of the 1834 having
  failed. It now subtracts every failing class, and a FAIL verdict states no green figure at all.
  Both mutants a reviewer wrote against the first version survived, because the test asserted the
  substring rather than the number; it asserts the number now. The two remaining return paths
  that omitted the scope disclosure the code's own comment claimed was universal carry it too.
