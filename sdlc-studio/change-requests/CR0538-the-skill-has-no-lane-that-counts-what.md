## Summary

Measured today by building every parser in-process: 71 scripts expose 211 verbs, and 49 of them (23%) appear in NO hand-written doc as `script.py verb`. Eight are absent from the entire 1.37 MB documentation corpus - `artifact.py retitle`, `critic.py caller-check`, `refine.py seams`, `retro.py collate`, `sprint_report.py operator-summary`, `verify_ac.py corpus-scan`, `verify_ac.py scaffold-matrix`, `verify_ac.py testplan`. Of 677 flags, 72 are named nowhere.

The drift is ONE-DIRECTIONAL, and that decides the remedy. Nothing in the docs promises a command that was removed, and script-level coverage is 71 of 71 across the `reference-scripts*.md` family. The prose is not wrong; it is incomplete. So this is a generation-and-measurement problem, not a rewrite.

What lets it accumulate is that nothing counts it. `doc_coverage.py` is hard and blocking, and asks only whether a SCRIPT has an entry - never whether the subcommands that entry offers are described. `disclosure.py`, the best-practice checker, is advisory by construction (`ok: True` is hardcoded) and is defined in package.json as `lint:disclosure` while being left OUT of the aggregate `lint` - so its 28 open findings are reported to nobody.

The structural misses compound it. SKILL.md carries no `## See Also`, which its own best-practices checklist requires, and its `## When to Use` is a single prose sentence - the exact shape that file gives as its BAD example. Twenty of 55 references are named nowhere in SKILL.md, including `reference-prd.md`, `reference-story.md`, `reference-trd.md` and `reference-tsd.md`, four core pipeline artefacts. Nine of 55 references carry a Reading Guide while 26 exceed the 400-line threshold SKILL.md itself sets for mandatory section-reading. And `check_budgets.py` permits `reference-sprint.md` at 827 lines on a justification that asserts TWICE that its Reading Guide anchors partial reads - it has no Reading Guide.

## Impact

Every agent and operator, on every project. A verb nobody can discover is a verb nobody uses, so the tooling is bought and not taken delivery of. The eight zero-token verbs are undiscoverable at any price short of reading the source.

## Acceptance Criteria

- [ ] The surface is ENUMERATED from the parsers that define it - subparsers, loop-built verbs and positional `choices` alike - by one library every reader shares, and a script that cannot be enumerated is NAMED rather than skipped
- [ ] The verb catalogue is GENERATED from that enumeration and regenerated by a command, so no hand-maintained copy exists to drift; the generator writes only between ownership markers and refuses a file that has none
- [ ] The coverage figure is measured against HAND-WRITTEN docs only - every generated target and generated region excluded - so the number cannot be satisfied by the generator's own output
- [ ] Each undocumented verb carries a DERIVED severity and is filed through the shipped filer, idempotently; the lane exits zero always and holds nothing
- [ ] The figure surfaces where the run already looks: a non-blocking gate lane, the lint aggregate that actually runs, and the close report
- [ ] Every reference over the threshold SKILL.md states carries a Reading Guide with an anchor AND a line span, so a section can be read by offset rather than found by grep
- [ ] SKILL.md carries the sections its own checklist requires, and every reference is reachable from it within two hops
- [ ] A budget ceiling's recorded justification is true: one naming a Reading Guide requires the file to have one, and the files sitting inside the tolerance are reported rather than silent

## Recommendation

Generate, measure, report - never block. The operator has ruled that the documentation lane files bugs and does not refuse, on the same terms as CR0537.

The one risk worth stating in the recommendation, because it would make this CR worthless: the moment a generated page lists all 211 verbs, a naive coverage query returns 100% and the gap vanishes without anything improving. That is BG0457's recorded defect - a document compared against a projection of itself - one layer up. The exclusion of generated regions from the measured corpus is the load-bearing criterion here, not a detail.

Third leg beside CR0535 and CR0536: CR0535 answers what a verb DEMANDS, CR0536 keeps the spec documents true, this one keeps the skill's own docs complete. It consumes CR0535's reporter rather than building a second inventory.
