## User Story

**As a** Maya Okafor
**I want** The Fixed and Done gates refuse a unit with uncovered added lines unless each is ruled equivalent with a reason, and the ruling is in the depth field
**So that** a unit is verified before the seat does it - Maya Okafor ships real features through a disciplined lifecycle, not ad-hoc edits, and the seats confirm rather than discover

## Acceptance Criteria

- [ ] **AC1** Given `review.line_coverage: block` and a unit with an uncovered added line in its Affects diff, when `transition.py set <unit> Fixed` (a bug) or `Done` (a story) runs, then the transition COLLECTS coverage by running the unit's own selectors under `verify_ac run --coverage` - never by reading a prior report - and refuses naming the file, the line and the ruling command; the same unit with every added line executed passes - the paired control. The fixture also seeds a PRIOR report on disk claiming `uncovered: 0` for the uncovered unit, so a build that reads the last report passes it and dies. `--coverage-report <path>` reuses a report only when the report's recorded Affects hash matches the current bytes; a mismatch is refused as stale.
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_transition.py::CoverageGateTests::test_an_uncovered_added_line_refuses_the_terminal_transition_and_a_covered_unit_passes
  - **Verified:** yes (2026-09-08)
- [ ] **AC2** Given an uncovered line ruled equivalent through `verify_ac.py coverage rule --id <unit> --file <path> --line <n> --reason <why>`, which writes a row into a `## Coverage Rulings` table INSIDE the artefact (file, line, content hash, reason, author, date - tracked, never in `.local/`), when the transition runs again, then it passes and the derived half of the `Verification depth` field carries the count of ruled lines, written through verify_ac's derive-and-seal path so the `derived-depth` lane accepts it. A reason shorter than the floor `retract` already enforces (`_RETRACT_REASON_MIN`, the same constant) is REFUSED naming the floor and writes no row - a ruling is not a free bypass of the gate - and a sufficient reason writes the row: the paired control.
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_transition.py::CoverageGateTests::test_a_ruled_line_passes_and_the_ruling_is_in_the_depth_field
  - **Verified:** yes (2026-09-08)
- [ ] **AC3** Given a ruling whose content hash the file no longer has, when the transition runs, then the ruling is stale, the gate refuses naming it stale, and the depth field does not count it - the rule the mutation ledger applies to its rows.
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_transition.py::CoverageGateTests::test_a_ruling_on_stale_bytes_does_not_satisfy_the_gate
  - **Verified:** yes (2026-09-08)
- [ ] **AC4** Given `review.line_coverage: report`, when the transition runs on a unit with uncovered lines, then it passes and prints `coverage: N uncovered added line(s)` with the lines; under `off` (written as the bare YAML word, which YAML 1.1 parses to False and the reader accepts as `off`) it prints nothing and calls no collector - asserted through a spy on the collector; a value outside `block`, `report` and `off` is refused naming the three, never read as `off`.
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_transition.py::CoverageGateTests::test_the_mode_decides_refusal_report_or_silence
  - **Verified:** yes (2026-09-08)
- [ ] **AC5** Given `review.line_coverage_after: <date>` compared to the unit's `Created` date as ISO-8601 strings (never through `parse_cutoff`, which parses numeric ids and raises on a date), when the transition runs, then a unit created before the date is exempt, a unit created ON or after it is judged (the fixture holds a unit created on the date), and a unit with no parseable `Created` field is judged, never exempted. This repository sets `block` from 2026-09-07: the three stories reaching Done through `sprint close --apply-signoff` after the gate lands are judged by it, and the three bugs Fixed before it lands carry a `verify_ac run --coverage` figure in their revision rows as a delivery obligation.
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_transition.py::CoverageGateTests::test_units_created_before_the_cutoff_are_exempt
  - **Verified:** yes (2026-09-08)
- [ ] **AC6** Given the `coverage` module absent - the interpreter that runs the selectors under coverage is `SDLC_COVERAGE_PYTHON` when set, else `sys.executable`, and the absence is detected on THAT interpreter by asking it to import `coverage` (US0815 AC3's seam) - when the transition runs under `block`, then it refuses naming the dependency; under `report` it prints `coverage: not measured - the coverage module is absent (pip install coverage, or review.line_coverage: off)` and passes; neither reads as covered.
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_transition.py::CoverageGateTests::test_a_missing_coverage_module_never_reads_as_covered
  - **Verified:** yes (2026-09-08)
- [ ] **AC7** Given a project that never set `review.line_coverage`, when the transition runs, then the mode in force is `report` - read from the fallback literal in transition.py, because `project_override` reads the project file only and merges no defaults - and `templates/config-defaults.yaml` carries `line_coverage: report` with a comment naming `coverage` as an optional dependency and how to adopt `block`; a `block` default would refuse every terminal transition in every upgrading project without the module.
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_transition.py::CoverageGateTests::test_the_shipped_default_is_report
  - **Verified:** yes (2026-09-08)
- [ ] **AC8** Given a unit whose Done or Fixed transition runs at `sprint close --apply-signoff`, AFTER the close chain has stamped the run `ended_at` (the shipped order: `_close_handoff` before `apply-signoff`), when the gate takes its base ref, then it reads the ref of the run whose approved batch names the unit, open or CLOSED - the ref belongs to the unit's run - so the close's own transitions are judged - the gate sits inside `transition.transition`'s pre-write gates, the seam `artifact.close` and `sprint close --apply-signoff` both reach, and the test drives it through `artifact.close`; a run whose batch does not name the unit is never read; with no such run and no `--base <ref>` on the transition it refuses under `block` naming `--base`, and under `report` prints `coverage: not measured - no base ref` and passes.
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_transition.py::CoverageGateTests::test_no_base_ref_refuses_under_block_and_is_reported_under_report
  - **Verified:** yes (2026-09-08)
- [ ] **AC9** Given a Python Affects file with added lines and no traced selector (the unit's verifiers are all `shell`, `grep`, `eval` or `http`), when the transition runs under `block`, then it refuses naming the file as `not measured` - not measured is not covered - and under `report` it prints the file the same way and passes.
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_transition.py::CoverageGateTests::test_a_not_measured_python_file_is_refused_under_block
  - **Verified:** yes (2026-09-08)

- [ ] **AC10** Given a test module that uses `unittest.mock` at a site where nothing binds the submodule - no module-scope import and none in the function itself - when the repository's hygiene sweep runs, then it names the module, the line and the function, because bare `import unittest` does not bind the submodule and only pytest imports it for the module: under the plain unittest runner the `module-alone` boundary lane and CI use, every assertion in that module goes unexecuted while the discovery suite stays green. A local import inside ANOTHER function does not count, since it binds only if that test happens to run first.
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_repo_hygiene.py::SubmoduleImportTests::test_every_use_of_unittest_mock_is_bound_where_it_is_used
  - **Verified:** yes (2026-09-08)
