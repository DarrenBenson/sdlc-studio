## Summary

tools/`check_neutrality.py` refuses a tracked file naming a private consuming project, matched against SHA-256 hashes in `_BLOCKED`. The operator has ruled three more consuming-project names private (generalise them to 'a consuming project'), but their hashes are not in `_BLOCKED`, so the guard passes while 64 tracked files carry them: 25 bugs, 18 change requests, nine shipped lessons (LL0013-LL0021, installed into every user's skill), stories, RFCs, retros, a review, an epic, decisions.md, CHANGELOG.md and one test module (scripts/tests/`test_reconcile.py).` The fourth name in this family is already blocked, which is why BG1112 (filed into this clone by a consuming project's session) had to be neutralised before it could commit.

## Steps to Reproduce

Run `python3 tools/check_neutrality.py`: it exits 0. Then `git grep -l -i -E -f <a file holding the three names>`: 64 files.

## Proposed Fix

Add the three hashes to `_BLOCKED`. Generalise each occurrence to 'a consuming project' (or 'that project' where the sentence already introduced it), keeping ids such as RPT0002 only where the sentence still reads. In `test_reconcile.py`, rename the fixture value rather than changing what the test asserts. The blocked hashes are listed in AC1's Verify line; the names themselves are never written.
