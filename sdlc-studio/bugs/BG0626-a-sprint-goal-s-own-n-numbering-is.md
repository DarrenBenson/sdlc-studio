## Summary

`run_state.goal_clauses` decides a goal is a list the moment `_OXFORD` (a comma followed by `and`) matches ANYWHERE in it, and then splits on `_CLAUSE_LIST` - every a comma and a space in the text. Prose commas are not clause boundaries, and a goal's own `(1)` ... `(5)` enumeration, which is the strongest signal an author can give about where their commitments divide, is never looked at. Measured on the corpus: round 46's goal, whose author numbered five commitments, comes back as 15 clauses including `with NO exceptions. (1) BG0621` and a bare `BG0618`. The docstring states the opposite of the behaviour - "a goal nobody wrote as separable commitments comes back as ONE clause rather than being shredded into commitments its author never made" - so this is a claim the code contradicts, not an undocumented edge.

The consequence is not cosmetic. `_recorded_clause_verdicts` keys a seat's per-clause answers by the CLAUSE STRING, so a seat can only answer clauses it can predict the splitter will produce. No seat has ever managed it: 0 of 3 in each of the last two rounds carried a `clauses` key at all, and the close's goal panel has therefore reported UNANSWERED for every clause of every run. That is the same shape as BG0616 and BG0591 - a panel that correct behaviour cannot make green - and it sits on the one surface that states whether the run met what it set out to do.

## Steps to Reproduce

1. Write a Sprint Goal that numbers its commitments, e.g. `... (1) A, with detail. (2) B. (3) C.` 2. Call `run_state.goal_clauses(goal)`. 3. It returns one fragment per comma, not one per number. Measured over the 41 distinct goals in `sdlc-studio/.local/goal-review.json`: round 45's 475 characters to 3 fragments, round 46's 1314 characters to 15. 4. Record a goal review and close the run: the clause panel reports UNANSWERED, and no achievable per-seat answer clears it, because a seat would have to guess the splitter's fragments verbatim.

## Proposed Fix

Read the goal's own enumeration FIRST: when the body contains two or more `(n)` markers in ascending order, split THERE and nowhere else, and let the numbering be the author's statement of where the commitments divide. For a goal carrying no such numbering, the present comma/semicolon heuristic is UNCHANGED - one rule ships, not two. That is a deliberate choice between the two repairs available, and the rejected one is recorded here because it reads as the more principled: making a bare a comma and a space stop being a boundary would be closer to what the docstring promises, but it silently re-clauses all 41 goals already stored and every close that reads them, for a benefit no unit in this batch can measure. Numbering-wins changes exactly two of the 42 goals stored today.

Two details the split must state, because a careless implementation satisfies a count-only criterion without either: the `(n)` marker is STRIPPED from the clause it opens, and the PREAMBLE before `(1)` is DISCARDED rather than kept as a clause of its own. Both follow from what a clause is for - a seat records a verdict against it, and `_recorded_clause_verdicts` matches on the exact string, so a clause carrying `(1)` plus its trailing space is a key nobody will type. A preamble is framing, not a commitment, and a run cannot meet it. So a goal with six markers yields exactly six clauses, never seven. The docstring must be corrected to state the rule that ships, since it currently describes neither.

## Impact

The clause panel is the close's answer to "did this run do what it said it would". It has been structurally unanswerable, so every close has printed UNANSWERED and every reader has learned to skip it. It also silently penalises the goals this project asks for: a goal with several explicit, measurable commitments shreds worse than a vague one-liner.

## Delivery ordering

`_recorded_clause_verdicts` (`sprint.py`:8480-8513) keys a seat's per-clause answers by the EXACT clause string and reads only `rounds[-1]`. A goal review recorded before this fix therefore carries keys from the old splitter, every post-fix lookup misses, and the close's clause panel prints UNANSWERED regardless. So this unit lands FIRST in its batch, and the goal review is RE-RECORDED afterwards - a new round, keyed to the post-fix clause strings - or the run cannot meet the clause this bug exists to make meetable. One further consumer moves with it: `judge_defects_against_goal` (`sprint.py`:8423) reads the same clause list, so the defects-vs-goal ruling on the same close is computed over six clauses instead of fifteen.
