## Summary

`artifact.py new`exposes`--verify`and documents it, but it is STORY-ONLY:`_story_acs`is the only renderer that emits a`- **Verify:**`sub-bullet, so`artifact.py new --type bug --ac X --verify Y`silently DROPS the verifier and omits the`**ACn**`marker too. Copying that path as a reference would copy a second defect, which is why this unit's scope names`artifact.py`as a model to fix rather than to follow.`file_finding.py file`- the command the doctrine names for filing every finding - exposes`--ac`and NO`--verify`, and its `--fields-file`schema has an`acs`key with no verifier counterpart. There is therefore no way to author an executable criterion through the shipped filer. The criteria it writes carry no`- **Verify:**`sub-bullet,`verify_ac run`reports 'NONE carries a Verify line, so nothing was executed', and`_done_verify_gate` is inert precisely BECAUSE zero non-manual verifiers are declared - so the unit walks to a terminal status on a hand-stamped Verification depth with no criterion ever run. Measured on the live corpus: 15 bugs carry criteria and zero Verify lines, 53 criteria in total, 12 of them Open - two thirds of the v5.1 disclosed set.

## Steps to Reproduce

1. `file_finding.py file --type bug --ac 'given x, when y, then z' ...` and observe there is no flag to attach a verifier.
2. Read the written artefact: the criterion has no `- **Verify:**` sub-bullet.
3. `verify_ac.py run --unit <id>` reports the criteria parsed and NONE carrying a Verify line.
4. `sprint.py breakdown --bugs Open` reports the unit as groomed regardless.
5. `conformance.unit_is_ungroomed` tests three shapes - no-criteria, placeholder, derived-only - and executability is not among them, which is why step 4 passes.

## Proposed Fix

Give `file_finding.py file`a`--verify`that pairs with`--ac`exactly as`artifact.py new`does, and an`acs`fields-file entry that carries its verifier alongside its text. Then close the gate that let this run for months:`unit_is_ungroomed`gains a fourth shape - a criterion carrying no executable verifier and no explicit manual marker - so a unit whose criteria cannot be executed is REFUSED by`sprint plan` rather than reported as groomed. The two halves matter separately: the flag makes the right thing possible, the gate makes the wrong thing refuse, and shipping only the flag leaves 15 corpus units unfixed and silent.

Byte-exact is the criterion, not decoration:`_md_safe`backtick-wraps any underscored token, so a`--verify`routed through it emits``pytest .../`test_x.py`::T::`test_y```- a selector no runner resolves, and under a shell verb a backticked token is command substitution.`artifact.py`:140 already records that a Verify line must never be markdown-safed

The refusal lives at`sprint plan`(AC3), which is the gate the operator authorised. Nothing escapes by filing thin: a unit with no criteria at all is already ungroomed under the`no-criteria` shape. What survives from the original is the discriminating oracle - the message is asserted on its CONTENT, never on the absence of an error string
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_file_finding.py::VerifierAuthoringTests::test_a_criterion_with_no_verifier_is_reported

Driven through the shipped command, not through`unit_is_ungroomed`: the claim is about what the planner does, and a library test on the predicate stays green when the wiring at `sprint.py`:2137 is deleted
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_sprint.py::VerifierGroomingTests::test_plan_refuses_a_unit_whose_criteria_cannot_be_executed
- [ ] **AC4** Given the new reason string, when `breakdown`and`plan`render it, then`_AC_MISS`carries an entry for it and neither command raises.`sprint.py`:2167 is a bare `_AC_MISS[ac_why]`over a three-key dict, so a fourth reason is a`KeyError`that takes down the planner for EVERY batch holding such a unit - the fix's own blast radius, and the reason`sprint.py` is in this unit's Affects at all
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_sprint.py::VerifierGroomingTests::test_every_ungroomed_reason_has_a_rendering
- [ ] **AC5** Given a unit whose `## Acceptance Criteria` section parses to ZERO criterion blocks, when the predicate is asked, then it answers UNGROOMED. A rule phrased "every criterion carries a verifier" is VACUOUSLY TRUE over an empty list, and the shipped scan counts 61 bug files in exactly that state, so without this row the largest sub-population passes silently
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_conformance.py::VerifierGroomingTests::test_a_section_that_parses_to_nothing_is_ungroomed
- [ ] **AC6** Given a unit whose criteria DO carry verifiers, when the predicate is asked, then it answers groomed - and the fixture is a LIVE corpus unit rather than a hand-built one, so the control sees the shapes the corpus actually holds. Without this row, answering UNGROOMED for everything satisfies AC3 and AC5 together
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_conformance.py::VerifierGroomingTests::test_a_verifier_bearing_unit_stays_groomed

The first draft of this criterion asserted "15 bugs, 53 criteria" - a figure from a hand-written script that no shipped command reproduces (`corpus-scan` reports 51 carrying no verifier and 61 unreadable), and which this sprint's own triage closures would move. Two counters that disagree is the defect class this unit sits in
