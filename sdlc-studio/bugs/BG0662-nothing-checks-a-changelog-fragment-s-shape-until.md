# BG0662: nothing checks a changelog fragment's SHAPE until the release cut, and 59 of 119 had drifted past it

> **Status:** In Progress
> **Severity:** Medium
> **Points:** 3
> **Affects:** .claude/skills/sdlc-studio/scripts/changelog.py, .claude/skills/sdlc-studio/scripts/tests/test_changelog.py, .githooks/pre-commit, tools/tests/test_precommit_lane_order.py, AGENTS.md
> **Evidence:** 2026-09-10, this tree at f763a89a: `changelog.py compose` refused at BG0581.md; a sweep of changelog.d found 59 of 119 fragments whose first line was not the marker. After repair, compose reports `would compose 119 fragment(s) into Added, Changed, Fixed`.
> **Created:** 2026-09-10

## Summary

`changelog.py compose` requires every fragment's first line to be `<!-- section: <name> -->`, and refuses the WHOLE run on the first one that is not - correctly, because folding is destructive and a partial compose is worse than none. Nothing checks that shape when the fragment is WRITTEN. No lane opens a fragment at all: `.githooks/pre-commit` never calls `changelog.py`, and `gate.py`'s changelog lane runs only `structure` and the hand-edit check. `changelog.py check` lists uncomposed fragments and exits 1 on ANY, so it could not be a commit lane even if wired (every unit's commit carries a fragment). A fragment in any other shape commits cleanly and sits there. Measured on this tree at the v5.1 cut: 59 of 119 fragments were unparseable - 27 headed `### <ID>`, 26 a bare bullet with no marker at all, 5 headed `### Fixed`, one prose paragraph. Every one had passed the gate on the commit that wrote it. The first thing that would have discovered the drift is the release cut itself, which is the single moment where a refusal costs the most and where the tempting remedy is `--apply` with the bad ones deleted by hand.

## Steps to Reproduce

1. Write `changelog.d/BG9999.md` whose first line is `### Fixed` rather than the marker.
2. Commit it. Every lane passes - no lane opens a fragment; `changelog.py check`, run by hand, lists it as pending (exit 1, as it does for any pending fragment) and names no shape fault.
3. At the release cut run `changelog.py compose`. It refuses on that one file and folds nothing, however many other fragments are well formed.
4. On this tree before the repair: 59 of 119 refused, the oldest from BG0581.

## Proposed Fix

Add a `changelog.py shape` verb that parses each given (or every pending) fragment through the same parser `compose` uses (`_parse`, taking the fragment's text so the working-tree and staged readers share it), names EVERY one that cannot be composed with `compose`'s own message rather than stopping at the first, and exits 1 ONLY on a malformed one. `shape --staged` judges what the commit will record, not the working tree: it lists `git diff --cached --name-only --diff-filter=d -- 'changelog.d/*.md'` (added, modified, renamed - never deleted, because the release cut's own commit stages the deletion of every fragment) and reads each STAGED blob (`git show :<path>`), so an untracked draft is not judged and a malformed blob repaired in the tree but not re-staged is. Wire it as a blocking `run "changelog-shape"` lane at the top level of `.githooks/pre-commit`, among the cheap static guards and before the suite selection, and name it in AGENTS.md's lane roster. A fragment is written by the same commit as the code, so the shape is decidable at exactly the moment the author is still there to fix it. Cheap: one `git diff` and one blob read per staged fragment.

The mixed tree is the positive control for the silent one: a verb that says nothing about anything passes the second half alone, and a verb that refuses every fragment passes AC1 alone
  - **Verify:** pytest .claude/skills/sdlc-studio/scripts/tests/test_changelog.py::FragmentShapeCheckTests::test_only_the_malformed_fragment_is_named_in_a_mixed_tree

  - **Verify:** pytest tools/tests/test_precommit_lane_order.py::ChangelogShapeLaneTests::test_the_lane_refuses_a_staged_malformed_fragment

Positive control in the same repositories: staging one malformed fragment as well makes the lane fail naming only that fragment, so the passes are not a dead lane
  - **Verify:** pytest tools/tests/test_precommit_lane_order.py::ChangelogShapeLaneTests::test_the_lane_passes_the_release_cut_a_well_formed_fragment_and_an_untracked_draft

  - **Verify:** pytest tools/tests/test_precommit_lane_order.py::ChangelogShapeLaneTests::test_the_agents_roster_names_the_lane

## Impact

A release cut is refused by the accumulated shape drift of dozens of past commits rather than by anything in the release, and the operator's fastest way out is to delete the fragments that refuse - which silently drops those units from the changelog.
