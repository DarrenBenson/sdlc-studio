Under the combined no-local-trap and immortal-feeder mutant, only SIGINT fails, on its own assertion, and SIGTERM and drop pass on their own merits. The ceiling is now 240 s. (5) The redundant-guard survivors are unchanged and remain by design: the remote exit-130 trap (:180), the local trap (:128) alone, the feeder's getppid watch (:124) alone, and the local trap's exit 0. The local trap and the feeder together are still KILLED. The child polls for the release file with no deadline (tools/tests/test\_remote\_gate\_runs.py:43-44), unlike the gate's own 180 s deadline (:51). `_RunsClone.cleanup` touches the release file and then removes the whole fixture directory straight away (:182-184), so the child misses the file. Once the gate times out, the child is orphaned and polls every 50 ms indefinitely. Only AC3's `finally` kills the recorded child pids. Executed: each of my seven runs that failed before the release (three AC1 timeouts, two AC2 failures and two interrupts-test failures) left one such child with its release directory gone, and a passing control left none. Re-run alone at c6f2239c (the reset removed, interrupts test), it behaved the same, and I killed every process of mine. Eight more children from runs made between 15:08 and 15:21 are still running on this machine: pids 1711354, 1717898, 1720453, 1720541, 1722079, 1722714, 1722780 and 1724793, with release paths under ~/.cache/sdlc-tmp/sdlc-tests-*. A `while True` feeder from a mutant run at 14:38 (pid 1694943) is also still running. I left all nine alone because they are not mine. This suite runs on the shared gate host for every push, so a red run there leaves processes running indefinitely, which is the condition this story exists to prevent. At f31862d8 the stub had no child, so the repair introduced this. Fix: give the child the gate's deadline, or have `_RunsClone.cleanup` kill the recorded gate and child pids as AC3's finally does; [new] low: the changelog's "The host's gate runs with SIGINT and SIGQUIT at their defaults" (changelog.d/US1076.md:11) is pinned for SIGINT only.
