## Summary

reference-review.md:452 states '`critic.py` refuses to issue a brief missing any of these practices, or a claim-inventory pass that omits one of the four prose surfaces, so the discipline holds by construction'. The two functions that would do it, `assert_brief_practices` (critic.py:3177) and `assert_brief_claim_pass` (critic.py:3202), are called only by tests: `cmd_brief` never calls either, and no other production module does. So the shipped doctrine describes a refusal the tool never makes - the silent-misleading shape LL0009 ranks above a loud failure, and the shipped-but-unwired gate LL0027 warns of. Reproduced at 51f264db (grep of scripts/ excluding tests/); found by the 2026-09-15 backlog sweep.

## Steps to Reproduce

1. `grep -rn 'assert_brief_practices\|assert_brief_claim_pass' .claude/skills/sdlc-studio/scripts --include=*.py | grep -v /tests/` - only the two definitions print.
2. Read reference-review.md:452-454, which claims the brief verb refuses.

## Proposed Fix

Call both checks on the rendered brief inside the brief verb before it is printed, refusing (non-zero, naming the missing practice or surface) rather than printing a brief that fails them. If a check cannot pass on a brief the tool itself renders, fix the renderer, not the check.

## Acceptance Criteria

Where each check binds, measured 2026-09-15 against `brief()` at HEAD: the standing-practices block is appended at EVERY delivery tier (critic.py `brief`, the line joining the inventory and the practices block), so a light-tier delivery brief carries all five practices and lacks only the claim inventory; a plan-review brief carries neither (five practices and four surfaces missing). So the practices check binds to every delivery brief, first-round and `--rejoinder`, at both tiers; the claim-pass check binds to full-tier delivery briefs, first-round and `--rejoinder`; a plan-review brief, first-round or rejoinder, meets neither. The seam: the tests patch the module's `_REVIEW_PRACTICES_BLOCK` or `_CLAIM_INVENTORY_BLOCK` and drive `critic.main` in-process, on a fixture unit whose own text names no practice sentence and none of the four surfaces or the three ruling words, so nothing but the patched block can satisfy a check; a rejoinder also quotes its prior verdict into the checked text, so every fixture prior verdict (`VERDICT:`/`ISSUES:`/`BLOCKING:` only) names no practice sentence, none of the four surfaces (matched case-insensitively) and none of the three ruling words either. The checks run in the brief verb, not inside `brief()`, which BG0672's fingerprint matcher also calls. Every refusal names only what is missing: the vocabulary refusal at HEAD rolls-call all three ruling words whichever is absent, so that message changes to name the missing word alone; `UNVERIFIABLE` occurs twice in `_CLAIM_INVENTORY_BLOCK`, so a test dropping it drops both. A light-tier delivery `--rejoinder` renders no claim inventory (measured at HEAD: exit 0, stdout equal to the `rejoinder_brief()` render at light, which the claim pass refuses), so only the practices check binds there - which is why AC2 runs the rejoinder refusal at `--tier light` as well as `--tier full`: at the derived tier the fixture renders full, and a practices check gated on the full tier inside the rejoinder branch would still refuse there.
